# 설치본 음성 연속 실행 — 2026-10-02

Alden 0.3.5의 설치된 Whisper → 상주 로컬 27B → Qwen3-TTS 어댑터로 동일한 합성 WAV 두 개를 네 번 연속 처리했다. **8/8턴 종료, 답변 4 → 12 반복, 오류 0**이다. 최신 turn/context 번호도 순서대로 증가했다. 별도 로컬 Whisper가 생성된 WAV를 다시 읽었을 때 숫자가 정확한 것은 **7/8**이었다. 첫 파일의 `셋자는 사입니다.`는 모호하여 정확한 발음으로 승인하지 않았다. 사람의 청취 검증이 남아 있다.

첫 턴의 STT+LLM+WAV 생성 합계는 **14.633초(n=1)**, 이후 7턴은 중앙값 **4.075초**, 범위 **3.122–5.281초**다. 실제 TTS는 MPS:0/BF16이었다. 네트워크 감사에서 허용된 연결은 `127.0.0.1:11234`뿐이었다. 명시적 종료 후 Whisper 캐시는 비었다. 남은 MPS 8 MiB는 측정 코드가 보관한 parameter 텐서를 포함한다. RSS·MLX·MPS는 통합 메모리에서 겹치는 범위이므로 합산하지 않는다. 이전 recursive_mutex 종료 오류는 재현되지 않았지만 근본 원인이 해결되었다는 근거는 아니다.

같은 설치 LLM 어댑터의 고정 한국어 문맥 3종×4회는 **12/12 사실 포함, 어댑터 오류 0**이었다. 첫 표시 내용 지연은 p50 **0.238초**, nearest-rank p95 **1.601초**이고 전체 답변은 p50 **0.452초**, p95 **1.972초**다. 작은 표본이며 상주 모델·prefix cache·공유 호스트의 다른 작업이 유지되었다. 이를 전후 성능 개선이나 일반적인 언어 품질로 보고하지 않는다. tokens/s는 미측정이다.

기존 1초 대기 실행은 엔진의 running 카운터 때문에 **2/12에서 중단**했다. 부분 기록을 보존했고 요청이 실행 중이면 새 측정을 시작하지 않았다. 측정 CLI에 `--drain-timeout`을 추가했다. 기본 1초를 보존하며 유한한 0–10초만 허용하고 실제 유휴 상태를 확인한다. 명시적인 5초 설정으로 12회를 마쳤다. 제품 추론 경로와 모델·서비스·설정은 변경하지 않았다.

이 근거는 미리 구간을 나눈 파일 입력과 WAV 생성까지다. 웨이크워드·VAD·사람의 마이크·스피커 재생·에코·끼어들기·물리 중단은 포함하지 않는다. 발화 종료부터 첫 스피커 재생까지의 지연과 p95는 여전히 미측정이다. [정제한 측정 기록](alden-voice-sustained-20261002.json)에 표본·단계·측정 범위와 원본 receipt hash를 보존한다.

기준선 이후 고정하는 다음 개선 목표는 첫 표시 p50 ≤0.300초/p95 ≤1.500초, 전체 답변 p50 ≤0.600초/p95 ≤2.000초, warm 파일 단계 중앙값 ≤4.000초다. 현재 첫 표시 p95는 **0.101초**, warm 중앙값은 **0.075초** 초과했다. 이 파일 단계 목표는 실제 재생 목표를 대신하지 않는다. 메모리는 현재 preflight 상한을 유지하면서 정상 pressure·swap 증가 없음과 측정 범위별 footprint를 확인한다. 목표를 맞추기 위해 모델이나 표본을 바꾸지 않는다.
