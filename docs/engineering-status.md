## Previous architecture summary

<h2 id="architecture">Architecture</h2>

The Tauri menu-bar panel is a core-only gold hologram with no interactive controls. Right-click the menu-bar tray icon to open the 960×880 settings window. Its desktop layout uses 58:42 columns with a 16px gap and switches to one column below 800px. Settings use plain Korean labels and contain no bulk-verification, feature-checklist, permission, model-owner, hardware, or index-diagnostic controls.

![Jarvis champagne-gold spherical core panel](../docs/architecture/jarvis-core-panel.png)

GraphRAG indexing and production `context-sync-local` both copy the live KakaoTalk database plus WAL/SHM sidecars into a consistent temp snapshot, then open only that copy read-only with `PRAGMA query_only`; copy instability or failure fails closed without opening the source database. GraphRAG drill-down reads the existing `knowledge-graph.sqlite3` only; a node click does not copy KakaoTalk or reindex.

```text
KakaoTalk macOS (local SQLCipher DB)
        |
        v isolated copy, then mode=ro + query_only
openkakao-cli
        |
        +-> context.sqlite3 (vectors / keyword)
        +-> knowledge-graph.sqlite3 (GraphRAG k-hop 2/3/10)
        |
        v
reply worker
        |
        +-> recommended on-device: MLX Qwen3.8 Flash-Next
        +-> host-capable on-device: MLX Qwen3.8 27B
        |
        v AX local-send
KakaoTalk composer
```

- bridge 자체의 장기 작업은 `desktop/src-tauri/src/python_bridge.rs`의 bounded `SafeJobEvent` registry가 추적한다. browser 작업은 `browser/running/0.7`, model swap은 `model_swap/swap/0.9`로 등록되고 최신순 최대 8건, 300초 만료를 적용해 snapshot의 `jobs`로 합친다. 직렬화 키는 `{jobId, kind, stage, load, time, errorCode}`뿐이며 대화 내용, prompt, task text, token/secret은 포함하지 않는다. `desktop/src/core/load-mapping.ts`와 `desktop/src/runtime-poller.ts`는 job load를 전역 core load에 반영하고, `desktop/src/ui.ts`는 설정 활동 줄에 진행 중 작업 수를 표시한다.
- Local MLX hardware detection, model residency/ownership checks, shared request leases, and swap rollback live in `scripts/auto_reply_ondevice.py` through `ModelResidencyManager` and the swap gate. The `flock` gate coordinates participating OpenKakao request paths; external MLX clients and server-side work after a client disconnect are not fenced or verified by it.
- Bounded tool runtime, owned Playwright browser use, voice control, and the emergency abort latch are implemented in `scripts/jarvis_tool_runtime.py`, `scripts/jarvis_browser_use.py`, `scripts/jarvis_voice.py`, and `scripts/jarvis_abort.py`. The resolved tree is committed as `browser/uv.lock` and the wrapper runs `uv run --frozen`, so a missing or stale lock fails closed instead of silently re-resolving.

### Verified results

- AX composer discovery: `openkakao-cli ax-probe` now reports `composer_found=true` with label `메시지 입력` in 73-187 ms for all four open KakaoTalk windows, against ~15,400 ms and `false` for the same windows before the fix. Two defects were fixed in `src/ax_send.rs`. First, `live_walk` returned `None` when it ran out of its time budget even though it had already collected matches, and the composer lookup used `?` on that result, so a window large enough to exhaust the walk could never yield a composer at all. Second, the scroll-area candidate test was called with `tables.is_empty()` while its `table_found` contract required the opposite polarity, which let a transcript scroll area nominate its own bubble `AXTextArea` as the composer. The strict `live_walk` contract is unchanged for every other caller (a truncated walk still reports `None`, because callers such as the transcript read must not treat truncation as proof of absence); a new `live_walk_partial` is used only for the composer path, where breadth-first order collects both scroll-area children before descending. `cargo clippy --all-targets -- -D warnings` is clean and `cargo test` reports 1102 passed / 0 failed. The fixed binary is restaged at the stable path the worker shells out to for `local-send`, so live workers use it without a restart. No real KakaoTalk send was performed.
- Hidden-panel render pause, measured (2026-09-23 KST): the acceptance criterion for a hidden menubar window is the app's own render-call count, not whole-machine GPU use, and no hidden-state check existed before this unit. The Chromium stub now answers the real visibility bridge (`plugin:event|listen`, `plugin:event|unlisten`, `window_is_visible`) and `window.__jarvisStub.emitEvent(name, payload)` calls the handler the bridge registered, the same way the Rust shell does. Seven new checks report `jarvis://visibility` subscribed, **0 frames / 0.0 fps over 1.5 s while hidden**, **0 runtime-snapshot polls over the same window**, 34 frames (22.64 fps) on re-show, 0 frames on blur, and 32 frames (21.3 fps) on focus; all 33 checks pass and the receipt is [jarvis-desktop-render-check.json](../docs/architecture/jarvis-desktop-render-check.json). The event name comes from one Python constant that a contract test pins against `desktop/src/core/lifecycle-wiring.ts`, so a rename fails the check instead of quietly asserting on a dispatch nobody subscribed to. `tests/test_jarvis_desktop_render_check.py` gained 9 `PauseOnHideContract` tests (35 pass); its mid-file `unittest.main()` also stopped silently skipping the last 10 tests when the file is run directly.
- Scheduled-reply source row, widened from the newest page (2026-09-23 KST): the worker-bound `local-send` attests the source row's author but looked for that row only inside `read_messages(chat_id, 20, None)`. A scheduled reply fires after a debounce window, so in an active room the source row is normally older than the newest 20 rows, and the preflight closed with `scheduled reply source row is unavailable` - 70 of the 202 recorded pre-AX send blocks in room 417, which then died as `stale_backlog` (1,919 rows in that room; its last real send was 2026-09-19 20:03:31). `LocalDbReader::read_message_by_log_id` now reads that one row directly from the same read-only snapshot and `resolve_bound_source_message` falls back to it; a genuinely missing row still fails closed, and the attestation tail and `require_expected_local_source_tail` fence are unchanged.
- Truncated transcript walk, retried instead of reported empty (2026-09-23 KST): `read_visible_messages` collapsed every error to an empty list, and the bound-send attestation reads "no rows" as a failed match, so one expired AX walk on a loaded machine blocked a send whose transcript was on screen - 97 of the same 202 blocks reported `matched 0 rows, 0 distinct values, 0 UTF-8 bytes`. `visible_message_rows_bounded` now retries **only** the truncation errors (`could not inspect the chat window AX tree`, `could not inspect chat rows`) on a bounded 6 s / 150 ms budget, while a completed walk that proves there is no message list still returns immediately, so no previously fast failure gains a delay. The retry repeats reads only and never lowers the `is_acceptable` attestation threshold. `cargo clippy --all-targets -- -D warnings` is clean and `cargo test` reports **1102 passed / 0 failed** (1096 before, plus 4 `resolve_bound_source_message` and 2 `ax_send` tests).
